## 一、資料結構 (Data Structures)

### Q1. Hash table 的平均查詢是 O(1)，這個 O(1) 是怎麼來的？什麼情況下會退化？
**評分重點**
- 講得出前提：均勻雜湊假設 (simple uniform hashing) + load factor α 維持在常數。
- chaining 下平均鏈長 = α，所以期望比較次數是 Θ(1 + α)。
- 退化情境：雜湊函數爛、對手刻意構造碰撞 (hash flooding)、load factor 沒控制 → 最壞 O(n)。
- 答錯方向：只背「攤平後是 O(1)」卻說不出 α 或均勻假設；把 rehash 的攤還成本跟查詢成本混為一談。
**追問**：如果你的 key 是使用者可控的字串，你會怎麼防 hash flooding？

### Q2. AVL tree 和 red-black tree 你會選哪個？為什麼實務函式庫（如 C++ `std::map`）大多選 red-black？
**評分重點**
- 兩者都是 O(log n)，差在平衡的「嚴格程度」：AVL 高度更矮 → 查詢略快；RB 旋轉次數少 → 插入/刪除較便宜。
- 插入/刪除後 AVL 可能需要 O(log n) 次旋轉，RB 的重新平衡旋轉次數是常數上界。
- 結論要落在 workload：讀多寫少選 AVL，讀寫混合選 RB。
- 答錯方向：只說「RB 比較快」而講不出讀寫比例這個判準。
**追問**：那 B-tree／B+ tree 為什麼在資料庫贏過這兩個？

### Q3. 要維護一個資料流，隨時能問「目前的中位數是多少」，你會怎麼設計？
**評分重點**
- 兩個 heap：max-heap 存較小一半、min-heap 存較大一半，維持 size 差 ≤ 1。
- 插入 O(log n)、查中位數 O(1)，並說得出 rebalance 的搬移動作。
- 能比較替代方案（排序陣列 O(n) 插入、BST + size 欄位）並說明取捨。
- 答錯方向：直接說「排序後取中間」而沒意識到這是串流、不能每次重排。
**追問**：如果還要支援「刪除任意一個已插入的值」，你的設計要怎麼改？

## 二、演算法 (Algorithms)

### Q1. Dijkstra 為什麼不能處理負權邊？舉個例子說明哪裡壞掉。
**評分重點**
- 核心是貪婪的正確性前提：節點一旦被取出就「定案」，這需要路徑成本隨長度單調不減。
- 要能舉出具體反例（三節點、一條負邊讓已定案節點應該被更新）。
- 補充 Bellman-Ford / Johnson 作為替代，以及負環會讓最短路徑無定義。
- 答錯方向：只回「因為會有負環」——沒有負環時 Dijkstra 一樣可能錯。
**追問**：Johnson's algorithm 用 potential function 重新加權，為什麼重新加權後的最短路徑跟原圖一樣？

### Q2. DP 和 greedy 的分界在哪？你怎麼判斷一個問題可以用 greedy？
**評分重點**
- 兩者都要 optimal substructure，差別在 greedy 還需要 greedy-choice property。
- 要能說出「怎麼驗證」：exchange argument 或 matroid 結構，而不是靠直覺試。
- 舉一組對照例：fractional knapsack (greedy 可) vs 0/1 knapsack (必須 DP)。
- 答錯方向：說「greedy 比較快所以先試 greedy」，講不出正確性怎麼保證。
**追問**：Huffman coding 是 greedy，你要怎麼證明它產生的是最佳前綴碼？

### Q3. 如果要你證明一個新問題是 NP-complete，大致步驟是什麼？
**評分重點**
- 兩步：(1) 證明在 NP（給 certificate，多項式時間驗證）；(2) 從已知 NP-hard 問題做多項式歸約到它。
- 歸約方向不能反：是「已知難問題 ≤p 新問題」，不是反過來。
- 歸約要證兩個方向的等價（yes-instance 對應 yes-instance）。
- 答錯方向：歸約方向講反，或漏掉「屬於 NP」這一半。
**追問**：NP-hard 跟 NP-complete 差在哪？舉一個 NP-hard 但不在 NP 的問題。

## 三、作業系統 (Operating Systems)

### Q1. Process 和 thread 的差別是什麼？context switch 的成本差在哪？
**評分重點**
- 資源面：process 各自有 address space、file table；thread 共享 address space，只有各自的 stack / registers / PC。
- 切換成本：thread 切換不用換 page table，所以不會整批 flush TLB；process 切換會。
- 能連到取捨：隔離性 vs 通訊成本，以及共享記憶體帶來的 race condition 問題。
- 答錯方向：只背「thread 比較輕量」而說不出 TLB / page table 這層原因。
**追問**：那為什麼 Chrome 要刻意用多 process 而不是多 thread？

### Q2. Deadlock 的四個必要條件是什麼？實務上作業系統通常選擇打破哪一個？為什麼？
**評分重點**
- 四條件：mutual exclusion、hold and wait、no preemption、circular wait。
- 實務多半處理 circular wait（資源排序）或 hold and wait，因為 mutual exclusion 常是硬需求、preemption 對多數資源不可行。
- 能區分 prevention / avoidance (Banker's) / detection + recovery，並說明為何 Banker's 實務少用（要事先知道最大需求）。
- 答錯方向：把四條件說成充分條件；或說「OS 都用 Banker's algorithm」。
**追問**：Linux 實際上對 deadlock 大多採取什麼態度？為什麼可以這樣做？

### Q3. 一次 page fault 從發生到處理完，流程是什麼？TLB 在裡面扮演什麼角色？
**評分重點**
- 流程：TLB miss → page table walk → valid bit 為 0 → trap 進 kernel → 找 free frame（不夠就跑替換演算法、必要時寫回 dirty page）→ 從 disk 載入 → 更新 page table 與 TLB → 重新執行該指令。
- TLB 是 page table 的 cache，命中就不用走 page table；要能區分 TLB miss ≠ page fault。
- 能提到 minor / major fault 的差別。
- 答錯方向：把 TLB miss 直接等同 page fault。
**追問**：為什麼 LRU 在硬體上不好實作？實際系統怎麼近似它？

## 四、計算機組織與結構 (Computer Organization & Architecture)

### Q1. Pipeline 的 hazard 有哪幾種？各自怎麼解？
**評分重點**
- structural（資源衝突，靠複製資源／分開 I-cache D-cache）、data（RAW/WAR/WAW，靠 forwarding、必要時 stall）、control（分支，靠 branch prediction、delay slot、提早算出分支結果）。
- 要說得出 forwarding 解不掉的情況：load-use hazard 至少要一個 bubble。
- 能連到 CPI：hazard 讓實際 CPI 高於理想的 1。
- 答錯方向：只列名詞不講解法，或說 forwarding 可以解掉所有 data hazard。
**追問**：out-of-order execution 是怎麼再把這些 stall 藏掉的？

### Q2. Cache 的 write-through 和 write-back 差在哪？多核心下為什麼需要 cache coherence protocol？
**評分重點**
- write-through 每次寫都同步到下層（簡單、一致性好、頻寬吃重，常配 write buffer）；write-back 只在 evict 時寫回（省頻寬，需要 dirty bit）。
- 多核心問題：同一份資料在多個私有 cache 有副本，一個核心改了其他核心會讀到舊值。
- 能講出 MESI 四個狀態的大意與 invalidation 的行為。
- 答錯方向：以為 write-through 就不需要 coherence protocol。
**追問**：false sharing 是什麼？它為什麼會讓多執行緒程式突然變很慢？

### Q3. 為什麼現在 CPU 不再往上衝時脈，而是往多核心發展？
**評分重點**
- 功耗牆：動態功耗 ∝ C·V²·f，且提高 f 通常要提高 V，功耗接近立方成長；散熱撐不住 (Dennard scaling 終結)。
- 記憶體牆與 ILP 已被壓榨到邊際效益遞減。
- 代價：把難題丟給軟體，受 Amdahl's law 限制，序列部分決定加速上限。
- 答錯方向：只說「摩爾定律失效」——電晶體數量成長和時脈停滯是兩件事。
**追問**：用 Amdahl's law 算一下：如果程式有 10% 是序列的，核心數無限多時最多加速幾倍？

## 五、離散數學 (Discrete Mathematics)

### Q1. 數學歸納法和強歸納法差在哪？舉一個非用強歸納不可的例子。
**評分重點**
- 弱歸納：假設 P(k) 成立推 P(k+1)；強歸納：假設 P(1)…P(k) 全成立推 P(k+1)。
- 關鍵認知：兩者**邏輯上等價**（強歸納可由弱歸納對「前 k 個都成立」這個命題推得），差別只在寫證明時方不方便。
- 例子要選遞迴會跳步的：任意 n ≥ 2 可分解為質數乘積、Fibonacci 相關恆等式、二人取物遊戲的必勝策略。
- 答錯方向：說「強歸納比較強、能證更多東西」。
**追問**：structural induction（對遞迴定義的結構做歸納）跟這兩者是什麼關係？

### Q2. 鴿籠原理看起來很簡單，講一個用它證出來的非顯然結果。
**評分重點**
- 先講清楚廣義形式：n 個物品放進 m 個籠子，必有一籠 ≥ ⌈n/m⌉ 個。
- 真正的難點是「設計對應」——什麼當鴿子、什麼當籠子，要能明講自己的設計。
- 好的例子：從 1…2n 任取 n+1 個數必有兩數互相整除；Erdős–Szekeres 單調子序列；任 6 人中必有 3 人互相認識或互不認識。
- 答錯方向：只複述原理本身，舉不出需要巧妙對應的例子。
**追問**：Erdős–Szekeres 說長度 n²+1 的序列必有長度 n+1 的單調子序列，鴿籠要怎麼套上去？

### Q3. Euler path 和 Hamiltonian path，判定的難度差在哪？為什麼差這麼多？
**評分重點**
- Euler：有簡潔充要條件（連通 + 奇數度頂點數為 0 或 2），線性時間可判、可構造。
- Hamiltonian：NP-complete，目前沒有已知的多項式判定法。
- 要說得出本質差異：Euler 的條件是**局部的**（每個頂點的度數），Hamiltonian 是**全域的**結構限制，局部資訊拼不出來。
- 答錯方向：以為兩者只差在「走邊 vs 走點」而難度相近。
**追問**：Euler circuit 實際上怎麼構造？（提示：Hierholzer）

## 六、線性代數 (Linear Algebra)

### Q1. 矩陣的 rank 有哪些等價的看法？rank 怎麼決定 Ax = b 的解？
**評分重點**
- 等價說法：row rank = column rank = 行空間維度 = 非零奇異值的個數 = 最大非零子行列式階數。
- rank-nullity：rank(A) + nullity(A) = n（A 的行數）。
- 解的判準：有解 ⟺ rank(A) = rank([A|b])；解唯一 ⟺ 再加上 rank = n；否則解空間維度 = n − rank。
- 答錯方向：只背定義，接不到解空間；或把 rank 跟矩陣是否方陣綁在一起。
**追問**：一個神經網路的線性層如果 rank 不滿，實際上代表模型損失了什麼？

### Q2. Eigenvalue 和 eigenvector 的幾何意義是什麼？什麼樣的矩陣保證可以對角化？
**評分重點**
- 幾何意義：Av = λv，該方向在線性變換下方向不變，只被縮放 λ 倍。
- 可對角化 ⟺ 有 n 個線性獨立的特徵向量 ⟺ 每個特徵值的幾何重數等於代數重數。
- 特徵值相異是**充分非必要**；實對稱矩陣則必可正交對角化（spectral theorem），且特徵值為實數。
- 答錯方向：把「特徵值相異」當成可對角化的必要條件。
**追問**：不可對角化的矩陣怎麼辦？你有哪些替代的分解可用？

### Q3. SVD 和 eigendecomposition 差在哪？為什麼 PCA 的實作通常走 SVD？
**評分重點**
- 適用範圍：SVD 對任意 m×n 矩陣都存在；eigendecomposition 只對方陣、且要可對角化。
- 關係：A = UΣVᵀ，奇異值是 AᵀA 特徵值的平方根，U、V 分別是 AAᵀ、AᵀA 的特徵向量。
- PCA 走 SVD 的理由是**數值穩定**：不必顯式構造 covariance matrix，避免條件數被平方放大。
- 加分：講得出 Eckart–Young——截斷 SVD 是 Frobenius / spectral norm 下的最佳低秩逼近。
- 答錯方向：說「SVD 就是 eigendecomposition 的推廣所以一樣」，講不出數值面的差別。
**追問**：為什麼保留前 k 個奇異值就是最佳的 k 秩逼近？你要怎麼說服我這件事？

## 七、機率與統計 (Probability and Statistics)

### Q1. 用「篩檢罕見疾病」的例子說明：為什麼一個準確率 99% 的檢測，驗出陽性仍可能大多是誤判？
**評分重點**
- 要能寫出 Bayes 並實際代數字：P(病|陽性) = P(陽性|病)P(病) / P(陽性)，盛行率極低時分母被偽陽性主導。
- 分清楚 sensitivity、specificity 與 PPV 是三件事，PPV 依賴 prevalence。
- 核心錯誤名稱要講得出來：base rate fallacy，把 P(陽性|病) 誤當成 P(病|陽性)。
- 答錯方向：直接說「99% 準所以九成九是真的」。
**追問**：如果要把 PPV 拉高，你會動哪個參數？代價是什麼？

### Q2. 大數法則和中央極限定理差在哪？CLT 在什麼情況下會失效？
**評分重點**
- LLN 講的是**收斂到哪**：樣本均值依機率／幾乎必然收斂到期望值。
- CLT 講的是**怎麼收斂**：標準化後的樣本均值分佈趨近常態，並給出 1/√n 的尺度。
- 失效情境：重尾分佈導致期望或變異數不存在（Cauchy）、樣本不獨立、極端偏態下小 n 的近似很糟。
- 答錯方向：把兩者混講成「n 大了就會變常態」。
**追問**：實務上你怎麼判斷手上的 n 夠不夠讓常態近似站得住？

### Q3. p-value 到底在講什麼？p = 0.06 可以說「兩組沒有差異」嗎？
**評分重點**
- 正確定義：在虛無假設為真的前提下，觀察到「至少這麼極端」結果的機率。它不是 H₀ 為真的機率，也不是效果大小。
- p ≥ 0.05 的正確結論是**未定**（沒有足夠證據拒絕 H₀），不能推成「沒有差異」或「兩者等效」。
- 要提到 statistical power：小樣本下就算真有差異也常常抓不到；應同時報效果量與信賴區間。
- 宣稱等效要用等效性檢定（TOST），事先設定等效界限。
- 答錯方向：把 p 解讀成「H₀ 為真的機率」或當成效果大小的指標。
**追問**：那你要怎麼設計一個真的能宣稱「兩者等效」的檢定？

## 八、專題：x-coach（結合知識檢索與多模態推理的可解釋性 AI 教練框架）

### Q1. 現在通用多模態模型已經能看影片給運動建議了，你這個系統存在的必要性是什麼？
**評分重點**
- 要把問題切成兩半：傳統 AQA 只給分不給理由；通用 LLM 給得出建議但無法溯源、容易幻覺。
- 你的差異化在「有據」：每一句建議都能追回檢索到的文獻節點與偵測到的幾何特徵，而不是模型自由發揮。
- 加上細粒度：能指出錯誤發生的時間區間與具體關節，而非整段影片給一個籠統評語。
- 答錯方向：把答案講成「我們準確率比較高」——面試官要的是定位，不是分數。
**追問**：如果我把你的知識圖譜整份塞進 GPT 的 context 當 prompt，你的系統還剩下什麼優勢？

### Q2. 你說 GraphRAG 能從「膝內扣」追溯到「臀中肌無力」，這個知識圖譜的邊是怎麼來的？怎麼確保它不是 LLM 抽出來的幻覺？
**評分重點**
- 說得出來源分層：FLEX 的 FKG 當骨幹 + 運科文獻抽取（`src/knowledge/extract_kg.py`）+ 人工審核的 canonical mapping。
- 要誠實面對「LLM 抽取」這段的風險，並講出你的控制：抽取結果保留出處、canonical 化避免同義節點爆炸、對照人工標註驗證。
- 能講出多跳推理的實際查詢路徑（錯誤術語 → 成因節點 → 訓練處方）。
- 答錯方向：宣稱「圖譜都是文獻來的所以不會錯」——抽取本身就是誤差來源。
**追問**：如果圖譜裡有一條邊是錯的，你的系統會在哪一步把它擋下來？還是會照樣輸出？

### Q3. 你的評估用 Spearman ρ 和 RAGAS，樣本數多少？在這個樣本數下，你有多少把握說系統真的比 baseline 好？
**評分重點**
- 要能直接講出目前的資料規模（Squat / REHAB24-6 各多少段、標註者幾人）而不是含糊帶過。
- 要把「效果量」和「顯著性」分開講，並知道小樣本下 p ≥ 0.05 只能說「未定」，不能說「兩者沒差」。
- 使用者測試只有 3–5 人，要主動承認那是質性回饋而非統計證據。
- 答錯方向：拿 demo 好看當證據；或把單一資料集上的結果講成通用結論。
**追問**：如果我只給你兩週和一台單卡機器，你會補哪一個實驗來讓這個結論最站得住腳？
