# Fitness-AQA 深度驗證實驗摘要

> 狀態:完成(2026-07-24)。五臂全數抽取完畢(MediaPipe 2D/3D、RTMPose 2D、
> NLF 2D/3D),NLF 在 Kaggle P100 上抽取,偵測率 98.7%,上下軸方向已驗證正確。
>
> **結論:在 Fitness-AQA 蹲深分類這個下游任務上,深度通道「不」改變分類結果**
> ——這與 Fit3D / REHAB24-6 的量測結論方向相反,但兩者其實一致,原因見下方解讀。

## 問題

Fit3D 與 REHAB24-6 有光學動作捕捉真值,深度誤差可以直接量測;結論是矢狀面的
深度判定受投影幾何破壞,而由影像直接回歸 3D 能取回深度軸。Fitness-AQA 沒有 3D
真值,是真實健身房的單機位手機影片,因此這裡只能問下游問題:**同一個偵測器、
同一組特徵、同一組切分,加上深度通道之後,分類結果會不會改變**。

## 資料選擇

用 `Squat/Labeled_Dataset/Shallow_Squat_Error_Dataset`,而不是影片層級的
`error_knees_forward` / `error_knees_inward`。理由:

- 這是逐幀的蹲深二分類,正是 Fit3D 上被量測到最受投影破壞的那個判定的野外版本。
  **標籤極性**:ReadMe 寫「0 = no error,1 = erroneous」,但實際看圖與量測都顯示
  `1` 類是**蹲得明顯較深**的幀(膝角中位 55° vs `0` 類 86.5°;髖低於膝 vs 髖高於膝),
  與資料夾名「shallow error」的字面直覺相反。對本實驗無影響——要問的是「加不加深度
  通道會不會改變分類」,與極性無關——但描述時一律當成「深/淺兩個深度類」,不硬套
  ReadMe 的 error/no-error 語意。人工檢視 test 各 8 張裁切圖確認此極性(class 1 明顯
  蹲到底,class 0 較淺或非蹲底)。
- 3,611 張蹲到底的單幀,不需要時序模型,也不需要 rep 切分,雜訊來源少。
- 官方 train/val/test id 清單彼此**影片不重疊**(train 440 / val 90 / test 93 支),
  切分洩漏不會膨脹比較結果。
- 類別接近平衡:全體 2,027 負 / 1,584 正。

輸入一律使用 release 自帶的 `crops_unaligned` 人物裁切圖。曾嘗試改用原始影片的
完整畫面(幾何條件較好),但把裁切圖對回來源影格在蹲底附近有 ±1 幀的模糊
(相鄰影格幾乎相同,樣板比對 8 例只有 1 例落在標註影格上),而各臂必須看到
逐位元相同的輸入,因此放棄完整畫面。

## 實驗臂

| npz | 來源 | 空間 | 意義 |
|---|---|---|---|
| `nlf_3d` | NLF `joints3d` | `cam3d`(mm) | 回歸出來的真深度 |
| `nlf_2d` | NLF `joints2d` | `image2d`(px) | **同一次前向傳播**,拿掉深度 |
| `mediapipe_3d` | BlazePose world landmarks | `cam3d`(mm) | 啟發式深度 |
| `mediapipe_2d` | BlazePose image landmarks | `image2d`(px) | 同一次推論,拿掉深度 |
| `rtmpose_2d` | RTMPose COCO-17 | `image2d`(px) | 強 2D 偵測器參考 |

能回答問題的是**同模型配對**:`nlf_3d` vs `nlf_2d`。跨模型比較(NLF vs MediaPipe)
把深度和偵測器品質混在一起,只當作背景資訊。

## 公平性設計

- **同樣的列**:任何一臂失敗的樣本,從所有臂一起剔除。
- **同樣的特徵**:`src/fitness_aqa/cue_features.py` 用 `src/fit3d/biomech.py` 的公式
  算 14 個無因次角度與比值;2D 與 3D 維度相同,3D 不會因為欄位比較多而佔便宜。
- **同樣的「上」**:`cam3d` 旋轉成垂直軸等於影像 `−y`,兩個空間對垂直的定義一致,
  差別只剩深度通道;兩者都不假設相機水平。
- **同樣的分類器**:L2 logistic regression,閾值在 val 上以 balanced accuracy 選定。
  故意用弱模型——要問的是特徵帶不帶得動訊號。
- **影片層級 cluster bootstrap**:同一支影片的多幀彼此相關,對幀重抽樣會假造精度。
  信賴區間與臂間差值都以整支影片重抽樣,並在相同 replicate 上配對。

## 解讀

**主要對比 `nlf_3d − nlf_2d = +0.003`(p=0.813)——在此任務上深度完全不改變分類。**
這乍看與 Fit3D / REHAB24-6「深度是瓶頸」相反,但拆開後三件事互相吻合:

1. **真正起作用的軸是偵測器品質,不是深度。** 三個強偵測器臂(nlf_2d、nlf_3d、
   rtmpose_2d)全部擠在 0.902–0.905,彼此差 <0.003 且不顯著;兩個 MediaPipe 臂
   落在 0.78–0.79。決定分數的是「用 NLF/RTMPose 還是 MediaPipe」(+0.12,p<0.001),
   不是「有沒有 z 通道」(+0.003,不顯著)。健全性檢查通過:nlf_2d ≈ rtmpose_2d
   (−0.002),兩個強 2D 偵測器群聚,先前 RTMPose 0.904 不是管線 artifact。

2. **深度是「多餘的」,不是被天花板擋住——直接量到。** 把 nlf_3d 與 nlf_2d 在同一批
   test 列上逐樣本比對:兩臂各錯 43 個,加深度後**修好 18、弄壞 18**,剛好互相抵銷;
   預測一致率 91.8%,分數相關 r = 0.943、rank r = 0.958。兩臂讀的是同一個訊號,不是
   「深度本來有用但沒 headroom」。這把 +0.003 從一個曖昧的空值升級成一個機制結論:
   **2D 與 3D 讀到的是同一個垂直線索。**

3. **為什麼同一個線索?蹲深本質是「垂直」關係,而垂直在影像平面裡是保留的。**
   深度(z,射向相機的軸)才是 2D 丟失的軸。Fit3D 量到的大誤差是**膝關節角度**
   (混了垂直與深度兩軸),而蹲深判定的核心是髖相對膝的**高度差**,這在任何非俯視
   視角的影像 y 軸上都讀得到。人工檢視也印證:兩類差在蹲多低(垂直),不在朝向相機
   的深度。因此 nlf_2d 的 `depth_ratio` / `hip_drop_ratio` 本來就帶得動分類。

4. **方法差異放大了這點:Fit3D 用固定生物力學閾值,這裡是「在同分布標註上訓練分類器」。**
   訓練分類器能吸收該視角分布下任何殘餘的 2D 訊號,固定閾值不能。Fit3D 表四的 76%
   翻轉是固定閾值的結果;換成學習式分類器,強 2D 偵測器就把差距補平了。

**一句話**:在這個下游、學習式、同分布的蹲深分類上,**深度不改變分類,偵測器品質才會**。

### 這對論文的意義:限定了跨模型故事

本實驗做了一件論文 REHAB24-6 分析沒做的事——**固定偵測器**再開關深度。論文的
NLF 0.668 vs MediaPipe 0.633 是**跨模型**比較,把「偵測器品質」與「深度品質」綁在
一起。這裡拆開來看:同偵測器開關深度 = +0.003(不顯著),換偵測器(NLF-2D vs
MediaPipe-2D)= +0.122(p<0.001)。因此論文那 0.035 的差,**至少有一部分是偵測器
品質而非深度**,不能全記在深度頭上。這比硬把結果凹成「與 Fit3D 一致」更誠實、也更
站得住腳:深度瓶頸是「線索精度 / 固定閾值判定」層級的真現象(Fit3D 直接誤差量測
已證),但在「訓練分類器 + 蹲深這種垂直判定」的下游設定,強 2D 偵測器即可追平真 3D。

## 統整實驗:整個 Squat 的三種錯誤(影片層級)

把同一套「同偵測器開關深度」的對比,從 shallow 擴展到整個 Squat 的所有錯誤型態:
`knees_forward`(膝前移,矢狀面)、`knees_inward`(膝內扣/valgus,額狀面)、以及兩者
聯集 `combined`。這些是影片層級標籤(時間區間→二分類),用影片層級聚合器
(`src/fitness_aqa/video_features.py`:逐幀 cue → 全片 + 姿態推導蹲底相位的
mean/std/percentiles,196 維)。**防洩漏**:蹲底相位只用髖高選幀,絕不碰標籤的時間區間。

資料:1,623 支影片,官方影片切分(train 1135 / val 243 / test 244);NLF 在 Kaggle P100
上抽取(1,622/1,623 有效,偵測率 99.7%;MediaPipe 全片 CPU;RTMPose 全片 ~28h CPU 故略過,
nlf_2d 即強 2D 臂)。逐幀 stride=3、每片上限 60 幀。2,000 次影片層級 bootstrap。

### 每種錯誤的同模型深度差(test n=244)

以 **AUC(免閾值)為主指標**,balanced accuracy 為輔。AUC 差跨四個錯誤 × 兩個偵測器,
只有一格為正:**NLF 真深度在 knees_inward 上 +0.080**;其餘皆略負,MediaPipe 啟發式
深度在 inward 上也只有 +0.007。

| 錯誤 | 平面 | nlf ΔAUC(3d−2d) | mp ΔAUC | nlf ΔBA | BA p |
|---|---|---:|---:|---:|---:|
| shallow(逐幀,另做) | 矢狀/垂直 | — | — | +0.003 | 0.813 |
| knees_forward | 矢狀/膝前移 | −0.028 | −0.022 | −0.007 | 0.863 |
| **knees_inward** | **額狀/valgus** | **+0.080**(0.825 vs 0.745) | +0.007 | +0.122 | 0.008 |
| combined | 混合 | −0.011 | −0.021 | +0.018 | 0.614 |

**先看 AUC 的理由**:knees_inward 的 balanced-accuracy +0.122 有兩個脆弱處,AUC 都避開了。
其一,閾值是在**只有 36 個 val 正例**上選的,recall 0.44→0.83 的跳動約等於 14 支影片的
閾值位置。其二,**raw accuracy 其實變差**(逐樣本 overlap:3D 修好 22、弄壞 38,淨 −16);
BA 上升純粹因為它把稀少的正類重新加權。ΔAUC=+0.080 是**免閾值的排序增益**,證明是真的
把 inward 正例排得更前,而不只是操作點位移。

### 這是「線索軸 × 視角」的精緻化,不是推翻論文

論文 §6.1 說:矢狀面(深度/屈曲)需要 3D,額狀面(膝內扣)由偵測器主導、2D 就夠。
野外資料的分布看似相反——三個矢狀/垂直錯誤深度都沒幫助,唯一需要真 3D 的是**額狀面的
knees_inward**——但兩者其實是同一條原則的不同視角實例。**論文對它的視角分布是對的;此
資料對它的後方/斜後視角分布也是對的。決定 3D 有沒有用的不是解剖平面,而是「該錯誤的判別
線索軸,在主導視角下是否被前縮進相機深度軸」。**

機制(係數 + 深度品質對照雙重佐證,非臆測):
- `knees_inward` 的 **nlf_3d 頭號特徵是 `bottom__knee_width_ratio`(valgus 線索,權重
  −2.41)**,但這個線索**不在 nlf_2d 的前六大特徵裡**——2D 讀不到,只好退回角度線索。
- **深度品質對照**:`mediapipe_3d − mediapipe_2d` 的 inward ΔAUC 只有 +0.007。要**真的
  回歸深度(NLF)**才有用,啟發式深度(MediaPipe)沒用——與論文 MeTRAbs vs MediaPipe 的
  「深度品質」結論一致。
- 此資料以**後方/斜後視角**為主(rear+rear_oblique ≈1485,side 138)。斜後視角把 valgus
  的**內外側**膝距前縮進深度軸,故只有真 3D 讀得回;蹲深(垂直)與膝前移(後視下仍部分
  反映在影像 y 與 shank 角)留在影像平面內,2D 就夠。**若換成側視為主的資料,論文的分流
  會成立**;此結論是視角相依,不是平面相依。

### 限制

- `knees_inward` test 36 個正例,且**每個正例都是不同的影片來源(36 個相異 id 前綴,
  無 subject/session 群聚)**,所以有效 N 確實是 36、影片層級 bootstrap 的獨立性假設成立;
  但 36 仍屬中等檢定力,是全實驗最該用更大樣本複驗的一點。AUC 與係數機制、深度品質對照
  三者一致,才是這個結論站得住的原因,而非單一 p 值。
- **蹲底相位是各臂用自己的髖高各自選幀**,故 3D 與 2D 可能摘要到略不同的幀,valgus 差有
  一小部分可能來自選幀而非深度本身;係數證據指向是線索本身,但完全乾淨的版本應跨臂固定
  蹲底幀集合。列為後續。
- 影片層級 BA/AUC(0.64–0.83)遠低於 shallow 逐幀的 0.90,granularity 不同,不可跨層級比
  絕對值;跨錯誤比較的是**同模型深度差**。
- `knees_forward` 訊號整體偏弱(各臂 AUC ~0.70–0.74),可能有天花板遮蔽;但 ΔAUC −0.028
  方向上偏負,不支持「膝前移需要 3D」。

### 與 shallow 合看的一句話

深度在 Squat 分類上**不是全有或全無,而是依「判別線索是否落在主導視角的深度軸」而定**:
垂直的蹲深、後視下的膝前移都留在影像平面(2D 足夠),唯有斜後視角把內外側 valgus 前縮進
深度的 `knees_inward` 真正需要、且只有真 3D 能提供的深度(ΔAUC +0.080,啟發式深度無效)。
這把「深度瓶頸」從平面標籤重新定位到「線索軸 × 視角」的交互作用上。

## 跨動作驗證:OHP + BarbellRow

把同一套「同偵測器開關深度」的對比接到另外兩個 Fitness-AQA 動作,檢驗深蹲得到的
「**線索軸 × 主導視角**」原則是否跨動作成立。特別設計了 mediolateral(內外側)線索
`elbow_flare`(OHP 的 valgus 類比),它在斜視角下會被前縮進深度軸;若「內外側線索需要
3D」跨動作成立,elbow_flare 應該像深蹲 valgus 一樣需要 3D,而所有矢狀面線索(膝、腰椎、
軀幹角)則 2D 就夠。

NLF 在 Kaggle P100 抽取(OHP 影片 2,260 支偵測率 99.7%;BarbellRow 逐幀 18,201 張
偵測率 92%,原始影像尺寸不一,kernel 內 letterbox 到 448² 再批次)。以下為 NLF-only
的同模型深度差(nlf_3d − nlf_2d),AUC 為主。

### 全部錯誤的深度差彙整(nlf_3d − nlf_2d)

| Squat | knees_forward | 矢狀 | −0.028 | 244 / 169 | 2D 足夠 |

### 判讀(先量測,再下結論)

**1. 矢狀面線索一致地不需要深度——強重現。** 跨三個動作、六個矢狀/垂直錯誤(shallow、
knees_forward、OHP knees、lumbar、torso_angle,以及各 combined),ΔAUC 全部落在
−0.035 ~ +0.003,無一為正,且多半 AUC 高(BarbellRow 0.90/0.98、OHP knees 0.88),
不是天花板遮蔽。「矢狀線索留在影像平面、2D 足夠」跨動作穩健成立。

**2. mediolateral 需要 3D:只有深蹲 valgus 一個強證據,跨動作沒有第二個乾淨的重現。**
全表僅有的兩個正 ΔAUC 是 Squat valgus(+0.080,顯著)與 OHP elbows(+0.013,不顯著)。

**3. 我原本用「視角」解釋 OHP elbows 為何沒重現——這個解釋被我自己的量測否證了。**
先前推測 OHP 偏正面、valgus 的深蹲偏斜後,所以只有深蹲的內外側線索被前縮進深度軸。
於是直接從 NLF 3D 相機座標量測兩個動作**內外側體軸落在深度軸的比例**(0=正面/影像平面,
1=側面/深度軸):

| 內外側軸 | Squat | OHP |
|---|---:|---:|
| 肩 L-R | 0.672 | 0.645 |
| 髖 L-R | 0.598 | 0.611 |
| 膝 L-R(valgus 軸) | 0.645 | 0.658 |
| 肩→肘(flare 軸) | 0.615 | 0.626 |

**兩個動作幾乎一模一樣(皆約 0.6–0.7,同樣偏斜)。OHP 並沒有比深蹲正面。** 所以「視角
不同」不能解釋為什麼深蹲 valgus 需要 3D 而 OHP elbows 不需要——這個 just-so story 死了。

**4. OHP elbows 沒重現的真正原因是任務太弱,不是視角、也不是線索壞掉。** 線索健全性檢查:
`elbow_flare` 100% 可算(過頭手臂沒有把它遮到 NaN),方向也對(error 0.755 > clean 0.732),
但**單一 flare 線索對標籤的 AUC 只有 0.581**,全任務 AUC 也才 0.66。一個逼近隨機的任務會
把任何深度差都衰減到 0,所以 OHP elbows 對「mediolateral 是否需要 3D」既不能證實也不能
證否——它是 inconclusive。

**修正後的誠實結論**:跨動作**強力重現了矢狀-null**(6 錯誤 / 3 動作),但**沒有**得到第二個
乾淨的 mediolateral 確認。深蹲 valgus 仍是唯一的強實例。而且在同等斜視角下 OHP elbows
沒有重現,代表**連深蹲內部得到的「線索軸 × 視角」原則,也還不能宣稱跨動作通則化**——
它作為深蹲**內部**(固定視角、變動線索軸)的發現成立,但要當跨資料集的通則,還需要更多
「斜視角 + mediolateral + 訊號夠強」的錯誤來檢驗。不要把它膨脹成「原則已通則化」。

### 限制

- 上面的深蹲內部結論(valgus vs 矢狀,固定視角)是乾淨的;跨動作把它外推去解釋 OHP
  的非重現則是事後、且已被深度比例量測否證,故不採用。
- OHP elbows 弱任務(AUC 0.66、單線索 0.58)使它 inconclusive;需要更強訊號的 mediolateral
  錯誤資料才能真正檢驗跨動作。
- BarbellRow 與 OHP 目前為 NLF-only(深度隔離主結果已足);MediaPipe 深度品質對照 OHP
  進行中、BarbellRow 待補。RTMPose 一律略過。
- 影片/逐幀 granularity 不同,只比同模型深度差,不比跨任務絕對值。

  `await run_in_threadpool(settings.allowed_upload_suffixes)`,而這個呼叫在冷快取下
  會做 Supabase round-trip;本機實測耗時 **6.98 秒**,超過測試 5 秒的輪詢死線,

  `allowed_upload_suffixes` stub 掉 → peak = 2 測試通過。這是既有 backend 程式
  (我沒動過)對 Supabase 網路延遲的敏感性,CI(該呼叫快)會過;與 torch 升級無關。
